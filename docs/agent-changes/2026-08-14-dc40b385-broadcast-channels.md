- **[#PR] Broadcast — channel subscription with per-subscriber dedup (task dc40b385, ADR-0093)**: adds `treadmill_api/messaging/broadcast.py` — `SubscriptionEvent` dataclass, `ChannelStore` (join/leave recorded as events with monotonic offsets; `subscribers_at(channel, up_to_offset)` folds to compute subscriber set at any point), and `fanout(channel, broadcast_id, payload, broadcast_offset, channel_store, emit)` which expands a broadcast to N unicast deliveries honoring three ADR-0093 rules: (1) subscriber set = fold at broadcast_offset; (2) dedupKey = composite `f"{subscriber}:{broadcast_id}"` — never a fresh UUID, never broadcast_id alone; (3) ordering_key = subscriber label for per-subscriber order. emit() injected (test spy / real log backend). Tests: 9 tests in `test_messaging_broadcast.py` — ONCE-PER-SUBSCRIBER with two non-vacuous foils: RED-a `_fresh_uuid_fanout` delivers alice twice on re-fanout; RED-b `_event_id_alone_fanout` + shared dedup delivers only alice (bob blocked as DUPLICATE); GREEN composite key + per-subscriber dedup delivers each exactly once, re-fanout blocked. ISOLATED-AT-BROADCAST: fanout emits for offline subscriber. JOIN-AFTER: subscriber who joined after broadcast_offset misses it. LEAVE-AFTER: subscriber who left after broadcast_offset still receives. Plus fold unit tests (join-then-leave, channel isolation, payload forwarding). Updates messaging AGENT.md: broadcast section + test navigation. Provenance: broadcast rules from ramjac ADR-0009.
