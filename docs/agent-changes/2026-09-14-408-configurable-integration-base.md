- [#408](https://github.com/joeLepper/treadmill/pull/408) — ADR-0114 (amends ADR-0110): a plan sets `integration_base` in its doc frontmatter (a git branch, default `main`). New nullable `plans.integration_base` column (migration `20260914_0100`), parsed from frontmatter (`PlanFrontmatter.integration_base`, with a validator rejecting `HEAD`/symbolic/whitespace/`origin/`-prefixed refs), stored + exposed on `GET /api/v1/plans/{id}`. The coordinator (§3.1a / §Drift / §9.7) cuts the per-plan feature branch off `origin/<integration_base>`, drifts against the same ref, verifies an existing branch descends from `<base>` (guarding a mid-flight base change), and — for a non-`main` base — opens NO branch→main handoff PR (the integration branch is the deliverable). `PlanHandoffPrOpened.pr_number` is now optional (a no-PR handoff has none; the drain gate keys on the event's existence). NULL base = `origin/main`, so existing plans are unchanged. Motivated by the first collaborator-repo dogfood (webhookless `netlify/agent-runner-orchestrator`, ADR-0113): tasks that read docs living only on a non-`main` branch, and a client repo whose `main` we must never touch. Cross-model panel (gpt + claude) + Ernie co-signed.
