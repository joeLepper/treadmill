# 2026-09-16 — ADR-0118: the evaluator verdict loop (rework re-dispatch + verdict-as-event)

- `events/task.py` + `events/registry.py`: `TaskEvaluatorVerdict` (the evaluator's verdict,
  POSTed as an event in router mode) and `TaskVerdictApplied` (the idempotency marker, keyed on
  the Event `commit_sha` column = head_sha).
- `coordination/dispatch_consumer.py`: `parse_verdict` (pure, total — never raises on a
  malformed record; tolerates a dict or JSON-string payload) + `_on_evaluator_verdict`. On a
  `task.evaluator_verdict` for a router task: `rework` bumps `tasks.generation` and re-dispatches
  the author at the new generation (trigger `evaluator-rework`); `approve` records the approval
  marker. EXACTLY-ONCE via the `(task_id, head_sha)` marker — a re-delivered/double-POSTed
  verdict no-ops. `head_sha` back-fills from the task's newest open PR when the poster omits it.
  SC6: router-substrate only.
- `routers/events.py`: `GET /api/v1/events` (filters `task_id`/`entity_type`/`action`,
  newest-first, bounded `limit`) — the read surface a router-mode worker uses to fetch its rework
  remediation (there is no coordinator to compose a brief).
- Team templates: the evaluator POSTs the verdict event in router mode (not cc-relay); the
  worker reads the newest `evaluator_verdict` remediation on a rework `task.ready` wake.
- Verified: 8 pure parse foils; 4 real-DB foils (rework bump + single re-dispatch + idempotent
  re-delivery; approve marker without dispatch; `head_sha` PR fallback; legacy-substrate skip);
  a `GET /events` handler foil. All 24 coordination DB foils pass against real Postgres.
- FOLLOW-ON: the `approve` → integration GIT MERGE of the approved head (the merge mechanism —
  plain PR-merge vs feature-branch integrate — and the integration-branch name source are an
  open design decision); the worker-assignment policy (still the phase-1 placeholder label).
